# V2 development: profiling and comparison contracts

This page describes the implementation on `v2-dev`. It is not the file format
produced by the published 1.x containers. Use the development checkout locally,
or build a matching container before running these workflows in containers.

## Shared preprofile assets

```bash
zipstrain utilities prepare_profiling \
  --reference-fasta reference.fna \
  --gene-fasta genes.fna \
  --stb-file reference.stb \
  --output-dir profiling_assets
```

Preprofile now writes `gene_info.parquet` rather than a gene-range TSV. Gene
headers use Prodigal's `name # start # end # strand # attributes` convention.
Coordinates are **one-based and inclusive**. Scaffold names are inferred by
removing the final `_number` portion of the gene name. Only translation tables
1 and 11 are currently supported; both use the same internal codon assignments.
Initiator-specific translation and frameshifted proteins are not modeled.
Optional `phase=0|1|2` and `transl_table=1|11` attributes override the defaults
of zero and 11. Phase skips bases at the coding 5′ end, including on minus-strand
genes. Prodigal `partial` flags are stored in coding orientation.

| Gene catalog column | Type | Meaning |
|---|---|---|
| `gene_id` | UInt64 | Content-derived identifier, not a row number |
| `gene` | String | Original annotation name |
| `genome` | String | Genome assigned by the STB |
| `chrom` | String | Reference scaffold |
| `start`, `end` | Int64 | Inclusive reference interval |
| `length` | Int64 | `end - start + 1` |
| `strand` | Int8 | `1` or `-1` |
| `phase` | UInt8 | Bases to skip before the first full codon |
| `genetic_code` | UInt8 | NCBI translation table |
| `partial_5p`, `partial_3p` | Boolean | Incomplete coding ends |

The adjacent **`reference_codons.parquet`** has `gene_id: UInt64`,
`codon_index: UInt32` (zero-based within the phased coding sequence), and
`reference_codon: String`. Triplets are in coding orientation. Incomplete final
triplets are omitted. Reference FASTA sequence is authoritative for these
triplets; the gene FASTA supplies annotations. Reference codons are written in
batches rather than retained as one Python object per codon for the full catalog.

BED, genome lengths, the null model, and the profiling contract remain shared
assets. With no gene FASTA, both annotation tables are valid typed empty Parquets.

### Preventing gene-ID mixups

A gene ID incorporates its genome, scaffold sequence identity, original name,
coordinates, strand, phase, and genetic code. Reordering FASTA records or genes
does not renumber genes. Changing the reference sequence or gene definition
changes the relevant IDs. A detected 64-bit ID collision fails explicitly.

The **whole mapping** is protected by `zipstrain_annotation_id` (SHA256 over
canonical catalog rows). `zipstrain_reference_id` identifies the normalized
reference sequences and scaffold-to-genome assignments, independent of FASTA
wrapping, case, descriptions, and record order. Profile and codon Parquets carry
these identities. Reference-codon contents are also bound to the catalog by a
file checksum. Comparisons reject missing/different identities and edited
catalogs before using gene IDs. Two unrelated tables containing the same integer
are not considered compatible.

Keep the original Parquets when transferring results. CSV exports do not retain
this metadata; preserve gene IDs as integer or string values without conversion
through floating point when analyzing exported tables.

## Per-sample outputs

The primary position profile contains:

```text
chrom, genome, pos, A, C, G, T, ref_base_bitmask
```

`ref_base_bitmask` is present when profiling used a reference FASTA. Neither
`gene` nor `gene_id` is stored per position. The sample's genome statistics remain
a separate Parquet. Positional SNV output also omits gene labels for V2 input.

The **gene-statistics table always has these 15 columns**:

```text
gene_id, genome, chrom, start, end, length,
coverage, breadth, ref_ani,
dN, dS, dN_dS, pN, pS, pN_pS
```

Coverage is retained depth summed across the interval divided by full gene
length. Breadth is the fraction of gene positions with positive retained depth.
Overlapping/nested genes each receive all positions in their own interval; a
position is stored once in the profile. Reference ANI uses sites of retained
depth at least 5 whose reference base is known. It is population reference ANI:
the reference allele must be present, not necessarily the majority. No callable
reference positions gives null ANI. Uncovered genes have zero coverage/breadth.

Without codon preparation, the six selection columns are null. Missing reference
information, missing selection evidence, and undefined ratios remain null; they
are not substituted with zero. No gene annotations gives a typed empty gene table.

### Observed codon evidence

```bash
zipstrain profile \
  --input-table samples.tsv --reference-fasta reference.fna \
  --stb-file reference.stb --gene-fasta genes.fna \
  --run-dir profiles --collect-codons --allele-integration consensus
```

`--prepare-dnds` is an alias for `--collect-codons`. The same switches are
available on `utilities profile-single`. This writes
`<sample>_codon_counts.parquet` and fills the gene selection metrics. Counts are:

```text
gene_id: UInt64, codon_index: UInt32, codon: String, count: UInt64
```

With `--backend rust_profiler`, the V2 Rust executable writes gene-free position
tables directly, including worker chunks. It does not read gene annotations or
create gene statistics. The shared Python/Polars finalizer uses the preprofile
catalog to create the same gene table and, when requested, makes an additional
BAM pass for observed codons and calculates the six selection metrics. Install
the V2 development plugin (`0.2.0.dev0`) with this checkout; its native binary no
longer accepts `--gene-range`.

These are **observed full triplets**, not combinations inferred by multiplying
three marginal nucleotide frequencies. Every retained observation:

1. Covers a complete reference codon on a single aligned read.
2. Has three A/C/G/T calls above the requested original Phred base-quality floor.
3. Contains no insertion, deletion, or reference skip within that triplet.
4. Passes the mapping-quality, read-ANI, and read-inclusion policies.
5. Uses only alleles retained in the final position profile at all three sites.

Minus-strand triplets are reverse-complemented into coding orientation.
Secondary, supplementary, duplicate, QC-failed, and unmapped alignments are
excluded. Overlapping mates with the same QNAME/read-group count once per codon:
choose the triplet with the greater minimum quality, and discard exact-quality
disagreements. Mate gaps are never filled. Reference-aligned codons after an
indel are not a reconstruction of a frameshifted protein.

Codon extraction uses original SAM base qualities; it does not independently
recalculate BAQ. The additional gate against the final position profile honors
its BAQ/error/frequency decisions at the allele level. Consequently complete-read
codon depth can be lower than marginal position depth. This stricter evidence
requirement is a V2 change from the marginal-count sidecars on `gene-overlap`.
Counts are flushed per scaffold, and the overlap cache expires as positions
advance. Selection grouping is staged to Parquet and read in batches.

Codon metadata identifies the evidence policy and the exact source position
profile checksum. A comparison rejects a codon table paired with a different
sample profile, even when both use the same reference and gene annotation.

## Selection method retained from `gene-overlap`

The estimator is identified as `sns_snv_reference_opportunities_v2`. It retains
the branch's **site-level SNS versus SNV split**, callable-reference opportunities,
and `consensus`/`weighted` integration rules. It does not introduce a corrected
evolutionary-distance estimator.

For each callable, non-stop reference codon, consider its nine possible single
nucleotide mutations. Each synonymous mutation contributes `1/3` synonymous
opportunity. Let their sum be `L_S`; nonsynonymous opportunities are `3 - L_S`.
Sum these opportunities over callable codons for the gene. Callability requires
at least 5 retained full-codon fragment observations by default; pairwise
calculations use codons callable in **both** samples. Incomplete, ambiguous, and
reference-stop codons do not contribute opportunities. Stop-producing changes
are not counted as ordinary synonymous/nonsynonymous events. As on the branch,
the possible stop-producing single mutations remain in the nonsynonymous
opportunity complement.

Define `D_N`, `D_S` as nonsynonymous/synonymous SNS consequences and `P_N`, `P_S`
as nonsynonymous/synonymous SNV consequences. Then:

```text
dN = D_N / L_N       dS = D_S / L_S       dN_dS = dN / dS
pN = P_N / L_N       pS = P_S / L_S       pN_pS = pN / pS
```

**There is no Jukes–Cantor or other multiple-hit correction.** These rates are
normalized event counts, not percentages, and are not restricted to 0–1. A zero opportunity
denominator produces null. A zero `dS` or `pS` produces a null ratio, including
`0/0`; valid zero change rates are zero.

Classification is at each nucleotide offset, not at the whole-codon level:

| Context | SNS events feeding dN/dS | SNV events feeding pN/pS |
|---|---|---|
| Sample versus reference | One retained allele differs from reference | More than one retained allele |
| Sample versus sample | Each side has one retained allele and they differ | Either side is polymorphic |

One codon can therefore contribute fixed SNS changes at one offset and
polymorphic SNV consequences at another offset.

### Allele integration

For reference-relative polymorphism, differing choices are **nonreference
alleles**. Consensus chooses the most-supported one, even if the reference allele
is more abundant overall; exact top ties divide one event equally. Weighted mode
uses each nonreference allele's fraction of the retained full-codon depth.

For pairwise polymorphism, differing choices are ordered unequal allele pairs.
Their support is the product of the two samples' allele counts. Consensus chooses
the maximum-support pair, dividing exact ties equally. Weighted mode uses the
product of the two observed allele frequencies. Matching pairs contribute zero;
weights are not renormalized after removing matches. Independent frequencies are
used **between samples**, not to invent haplotypes within a read population.

For example, reference `AAA` and observed `AAG:8, AAC:2` give a synonymous SNV
event of 1 in consensus mode; weighted mode gives synonymous weight 0.8 and
nonsynonymous weight 0.2. Rates then divide these by the reference opportunities.

Pairwise pN/pS is consequently a measure of polymorphic allele-pair consequences;
two identical polymorphic populations can still have positive values. It is not
defined as a difference between the samples' profile pN/pS values.

### Correct coding context

V2 fixes the branch's known single-base-in-reference-background problem.
Consequences use the **full reference/observed codon pair**, or the full two
observed codon contexts for a sample pair. For multiple differing positions, all
shortest substitution orders that avoid intermediate stops are averaged. Each
offset receives its share of those path consequences. Observed contexts
conditional on a selected allele choice are weighted by their support.

Thus samples `GGA` and `GGT` are synonymous even if the reference is `AAA`.
The other two shared nonreference bases are not replaced with reference bases.
This is a deliberate correction; affected multi-variant codons may differ from
the old branch's results. The counting approach follows the framework of
[Nei and Gojobori (1986)](https://doi.org/10.1093/oxfordjournals.molbev.a040410),
but these raw SNS/SNV proportions are **not** the full corrected NG86 estimator.

Method and allele-integration settings are recorded in gene-statistics and
comparison Parquet metadata. The gene-statistics table stores all six final values
for filtering. Comparison tables store the four rates and drop `dN_dS` and `pN_pS`,
which are costly at comparison scale and exact to derive:

```python
from zipstrain.gene_info import with_selection_ratios

comparisons = with_selection_ratios(pl.scan_parquet("all_comparisons.parquet"))
```

`gene_info.with_selection_ratios` returns null when `dS` or `pS` is zero or null,
matching the gene-statistics table. Intermediate event counts remain derivable from
the codon evidence and are not additional columns in either table.

## Comparison inputs and commands

```bash
zipstrain utilities compare-pair \
  --profile-1 profiles/A/A_profile.parquet \
  --profile-2 profiles/B/B_profile.parquet \
  --preprofile-dir profiles/profiling_assets \
  --calculate genome_ani+max_identical_stretch+gene_ani+gene_selection \
  --codon-counts-1 profiles/A/A_codon_counts.parquet \
  --codon-counts-2 profiles/B/B_codon_counts.parquet \
  --allele-integration weighted --output-file pair_result.parquet
```

Genome ANI and stretches only need the position profiles. Gene ANI additionally
needs `gene_info.parquet`; selection calculations also need the two observed
codon tables and the matching reference-codon definitions. Sample gene-statistics
summaries are not inputs to pairwise calculations.

`compare-pair` is the only pair-level comparison command. `zipstrain compare`,
Slurm and container runs, and Nextflow all run it per pair. It writes one
Parquet table, and the selected metrics determine the key and columns for the
whole table.

| Selection | Row key | Metric columns |
| --- | --- | --- |
| Genome metrics only | `sample_1`, `sample_2`, `genome` | Requested genome ANI and/or `max_identical_stretch`. Genome ANI includes `total_positions` and `share_allele_pos`. |
| Any gene metric (`gene_ani` or `gene_selection`) | `sample_1`, `sample_2`, `genome`, `gene_id` | Requested gene and genome metrics, plus `gene_total_positions` and `gene_share_allele_pos`. |

When both levels are requested, genome metrics repeat for each qualifying gene
in the genome and sample pair. To summarize a genome metric from this table,
deduplicate by `sample_1`, `sample_2`, and `genome` first. A genome without a
qualifying gene has no row in gene mode. Run genome metrics alone for complete
genome coverage. Gene rows require at least `--min-gene-compare-len`
positions callable in both samples. `zipstrain_compare_kind` records `gene` or
`genome` in the Parquet metadata.

Row order is not guaranteed, so join or sort by these keys rather than relying
on position.

`--calculate` takes these metrics, combined with `+`, on every entry point. Each
metric adds its columns in this order:

| Metric | Adds |
| --- | --- |
| `gene_ani` | `gene_total_positions`, `gene_share_allele_pos`, `gene_ani` |
| `gene_selection` | `gene_total_positions`, `gene_share_allele_pos`, `dN`, `dS`, `pN`, `pS` (requires `--collect-codons`) |
| `genome_ani` | `total_positions`, `share_allele_pos`, `genome_ani` (null without shared positions) |
| `max_identical_stretch` | `max_identical_stretch` |

`all` means every metric the inputs support, and `zipstrain_compare_calculate`
records what ran. Gene metrics are skipped with a warning when no gene catalog is
available, and `gene_selection` is skipped with a warning when no sample has a codon
table. Codon tables for only some samples are an error. Naming a metric the inputs
cannot support is also an error. Undefined metrics are null. V1 and V2 profiles
cannot be compared with each other.

`--min-gene-compare-len` defaults to 1 on every entry point, so a table keeps every
gene with a shared position and analyses can filter further. The plotting functions
in [downstream analysis](downstream.md) apply 100. For genome-only runs it has no
effect, is recorded as `NA`, and does not invalidate cached pairs.

Without `--preprofile-dir`, `compare-pair` calculates genome metrics only. With
`--pair-table` it compares many pairs in one process, also for genome metrics
only. `--scope GENOME:GENE` limits gene rows. The Nextflow workflow supports all
metrics, including `gene_selection`: its compare jobs receive the codon tables
found beside each profile.

For a collection:

```bash
zipstrain compare --profile-db profiles.csv --run-dir comparison \
  --preprofile-dir profiles/profiling_assets \
  --calculate genome_ani+max_identical_stretch+gene_ani+gene_selection
```

The collection writes one `all_comparisons.parquet`. Use `--force-csv` for an
additional CSV copy. The V2 table method runs locally with Polars. It discovers
conventional sibling codon filenames; the Python API accepts explicit per-sample
paths. Each completed pair is cached with a content-addressed input/settings
contract in Parquet metadata. Adding samples reuses complete matching pairs.
Changed profiles, codon evidence, annotations, filters, methods, or integration
settings never reuse a stale pair. Final outputs are atomically replaced.
Use `compare-pair` inside independently managed jobs when scheduling externally.

`--method table` is the default. Profiling establishes coordinate order and
records `zipstrain_sorted_by=chrom,pos` in the Parquet footer. When both inputs
carry that marker, table comparison passes the declared order directly to Polars
for a streaming merge join on `(chrom, pos)`. Stretch calculations and gene
interval sums reuse the result order. [Polars streaming joins](https://pola.rs/posts/streaming-joins/)

Profiles without the marker use a regular coordinate join followed by a sort.
If you reorder a profile outside ZipStrain, remove the marker or run
`zipstrain utilities sort-profile` to restore the promised order.

`--method matrix` supports the same V2 metrics and combined gene output. Pass
`--stb-file` and `--bed-file` as usual for the matrix store. With `gene_selection`, both
methods use the sibling observed codon tables produced by `--collect-codons`,
the same coverage threshold, and the same `--allele-integration` modes. The
matrix method requires the default `anchor` kernel for gene position counts.
The `block` kernel supports genome ANI only.

```bash
zipstrain compare --method matrix --profile-db profiles.csv --run-dir matrix_comparison \
  --stb-file reference.stb --bed-file profiles/profiling_assets/genomes_bed_file.bed \
  --preprofile-dir profiles/profiling_assets --calculate all \
  --allele-integration weighted
```

Matrix selection runs on the CPU in NumPy batches, regardless of the ANI
backend. It stages sparse observed codon counts per sample, joins callable
codons, and looks up synonymous and nonsynonymous consequences for observed
codon pairs. Weighted mode multiplies their frequencies. Consensus uses the
highest allele-pair support at each offset and splits ties, as in table mode.
Completed selection pairs are cached separately from the matrix ANI results,
so adding samples reuses old pairs. Use a fresh run directory when enabling
selection on an existing matrix whose input profiles were never fingerprinted
by the selection workflow.

The release benchmarks compare table and matrix selection on both genome
layouts and integration modes. [Benchmark charts](benchmarks.md#dnds-and-pnps-benchmarks)

Known profiling-filter differences are rejected when aligning samples.

`compare-pair` also reads 1.x profiles: `gene_ani` on its own gives the legacy
per-gene table. New gene-free inputs require shared annotations for gene
calculations. Legacy profiles and TSV ranges remain
readable by the existing legacy comparison/matrix adapters; new profiling
annotations must be the authenticated Parquet catalog.

### Nextflow

Use `--collect_codons true` (or `--prepare_dnds true`) and
`--allele_integration consensus|weighted` for profiling. The workflow stages
`gene_info.parquet` and `reference_codons.parquet` together. For V2 gene ANI,
pass `--preprofile_dir /path/to/profiling_assets`. Nextflow stages the directory
into single and batched comparison tasks. `--mode compare` is the one comparison
mode: `--compare_calculate` selects the row level and columns described above,
`--compare_scope` limits rows, and `--allele_integration` applies to
`gene_selection`. Each sample's `<sample>_codon_counts.parquet` is staged when
it sits beside the profile, so `all` includes `gene_selection` once every sample
has one.

### Scheduled runs

`zipstrain compare --execution-mode slurm` and container engines run V2 pairs through
the same `compare-pair` command as Nextflow. The metrics are resolved once for
all samples before any job starts, so a missing codon table fails the run up front
instead of giving pairs with different columns.

## Output formats frozen for 2.0

`tests/test_format_contract.py` pins these from a real run, from BAM through both
comparison methods. Changing a column, its type, its order, or a listed metadata key
fails that test. Such a change needs a new `zipstrain_profile_schema` value, because
readers reject any value they do not know.

| File | Columns (Parquet type) |
| --- | --- |
| `gene_info.parquet` | `gene_id` UInt64, `gene` String, `genome` String, `chrom` String, `start` Int64, `end` Int64, `length` Int64, `strand` Int8, `phase` UInt8, `genetic_code` UInt8, `partial_5p` Boolean, `partial_3p` Boolean |
| `reference_codons.parquet` | `gene_id` UInt64, `codon_index` UInt32, `reference_codon` String |
| `<sample>_profile.parquet` | `chrom` String, `genome` String, `pos` Int32, `A` `C` `G` `T` Int32, `ref_base_bitmask` UInt8 |
| `<sample>_codon_counts.parquet` | `gene_id` UInt64, `codon_index` UInt32, `codon` String, `count` UInt64 |
| `<sample>_gene_stats.parquet` | `gene_id` UInt64, `genome` String, `chrom` String, `start` `end` `length` Int64, `coverage` `breadth` `ref_ani` `dN` `dS` `dN_dS` `pN` `pS` `pN_pS` Float64 |
| `all_comparisons.parquet` | `sample_1` `sample_2` `genome` String, `gene_id` UInt64, `gene_total_positions` `gene_share_allele_pos` Int64, `gene_ani` `dN` `dS` `pN` `pS` Float64, `total_positions` `share_allele_pos` Int64, `genome_ani` Float64, `max_identical_stretch` Int64 |

`all_comparisons.parquet` holds the columns of the metrics that ran, in this order, and
`zipstrain_compare_calculate` records which those were. Its row order is not part of the
format. `zipstrain_compare_engine` records `table` or `matrix`; the two methods write the
same columns and values. Matrix stores, pair caches, and other files under
`intermediate_files` are internal and carry no compatibility promise.

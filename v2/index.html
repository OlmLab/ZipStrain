ZipStrain V2 profiling and comparison formats

This page describes ZipStrain 2.0.0b2. Install it with python -m pip install "zipstrain==2.0.0b2" or use the container image parsaghadermazi/zipstrain:2.0.0b2. For Nextflow, select the matching pipeline with -r v2.0.0b2.

Shared preprofile assets

zipstrain utilities prepare_profiling \
  --reference-fasta reference.fna \
  --gene-fasta genes.fna \
  --stb-file reference.stb \
  --output-dir profiling_assets

Preprofile now writes gene_info.parquet rather than a gene-range TSV. Gene headers use Prodigal's name # start # end # strand # attributes convention. Coordinates are one-based and inclusive. Scaffold names are inferred by removing the final _number portion of the gene name. Only translation tables 1 and 11 are currently supported; both use the same internal codon assignments. Initiator-specific translation and frameshifted proteins are not modeled. Optional phase=0|1|2 and transl_table=1|11 attributes override the defaults of zero and 11. Phase skips bases at the coding 5′ end, including on minus-strand genes. Prodigal partial flags are stored in coding orientation.

Gene catalog column Type Meaning
gene_id UInt64 Content-derived identifier, not a row number
gene String Original annotation name
genome String Genome assigned by the STB
chrom String Reference scaffold
start, end Int64 Inclusive reference interval
length Int64 end - start + 1
strand Int8 1 or -1
phase UInt8 Bases to skip before the first full codon
genetic_code UInt8 NCBI translation table
partial_5p, partial_3p Boolean Incomplete coding ends

The adjacent reference_codons.parquet has gene_id: UInt64, codon_index: UInt32 (zero-based within the phased coding sequence), and reference_codon: String. Triplets are in coding orientation. Incomplete final triplets are omitted. Reference FASTA sequence is authoritative for these triplets; the gene FASTA supplies annotations. Reference codons are written in batches rather than retained as one Python object per codon for the full catalog.

BED, genome lengths, the null model, and the profiling contract remain shared assets. With no gene FASTA, both annotation tables are valid typed empty Parquets.

Preventing gene-ID mixups

A gene ID incorporates its genome, scaffold sequence identity, original name, coordinates, strand, phase, and genetic code. Reordering FASTA records or genes does not renumber genes. Changing the reference sequence or gene definition changes the relevant IDs. A detected 64-bit ID collision fails explicitly.

The whole mapping is protected by zipstrain_annotation_id (SHA256 over canonical catalog rows). zipstrain_reference_id identifies the normalized reference sequences and scaffold-to-genome assignments, independent of FASTA wrapping, case, descriptions, and record order. Profile and codon Parquets carry these identities. Reference-codon contents are also bound to the catalog by a file checksum. Comparisons reject missing/different identities and edited catalogs before using gene IDs. Two unrelated tables containing the same integer are not considered compatible.

Keep the original Parquets when transferring results. CSV exports do not retain this metadata; preserve gene IDs as integer or string values without conversion through floating point when analyzing exported tables.

Per-sample outputs

The primary position profile contains:

chrom, genome, pos, A, C, G, T, ref_base_bitmask

ref_base_bitmask is present when profiling used a reference FASTA. Neither gene nor gene_id is stored per position. The sample's genome statistics remain a separate Parquet. Positional SNV output also omits gene labels for V2 input.

The gene-statistics table always has these 15 columns:

gene_id, genome, chrom, start, end, length,
coverage, breadth, ref_ani,
dN, dS, dN_dS, pN, pS, pN_pS

Coverage is retained depth summed across the interval divided by full gene length. Breadth is the fraction of gene positions with positive retained depth. Overlapping/nested genes each receive all positions in their own interval; a position is stored once in the profile. Reference ANI uses sites of retained depth at least 5 whose reference base is known. It is population reference ANI: the reference allele must be present, not necessarily the majority. No callable reference positions gives null ANI. Uncovered genes have zero coverage/breadth.

Genome statistics differ on purpose. The error filter also removes a position's only allele when too few reads support it (a single read, with the default model), so retained depth under-reports genomes below about 2x coverage. coverage, coverage_median, coverage_std, breadth and ber in <sample>_genome_stats.parquet are therefore counted from the depth before that filter, over every position with a read. The other genome columns, the gene table and the profile use retained counts. Positions with zero retained counts remain in the profile, preserving the genome inventory for comparisons.

Without codon preparation, the six selection columns are null. Missing reference information, missing selection evidence, and undefined ratios remain null; they are not substituted with zero. No gene annotations gives a typed empty gene table.

Observed codon evidence

zipstrain profile \
  --input-table samples.tsv --reference-fasta reference.fna \
  --stb-file reference.stb --gene-fasta genes.fna \
  --run-dir profiles --collect-codons --allele-integration consensus

--prepare-dnds is an alias for --collect-codons. The same switches are available on utilities profile-single. This writes <sample>_codon_counts.parquet and fills the gene selection metrics. Counts are:

gene_id: UInt64, codon_index: UInt32, codon: String, count: UInt64

With --backend rust_profiler, the V2 Rust executable writes gene-free position tables directly, including worker chunks. It does not read gene annotations or create gene statistics. The shared Python/Polars finalizer uses the preprofile catalog to create the same gene table. When requested, the Rust executable extracts observed codons in an additional BAM pass and the shared finalizer calculates the six selection metrics. To use the optional V2 plugin, install ZipStrain 2.0.0b2 in your environment first. The core beta wheel is also available from the GitHub prerelease. Then install the profiler beta and select it with --backend rust_profiler.

python -m pip install "zipstrain-rust-profiler==0.2.0b2"

These are observed full triplets, not combinations inferred by multiplying three marginal nucleotide frequencies. Every retained observation:

  1. Covers a complete reference codon on a single aligned read.
  2. Has three A/C/G/T calls above the requested original Phred base-quality floor.
  3. Contains no insertion, deletion, or reference skip within that triplet.
  4. Passes the mapping-quality, read-ANI, and read-inclusion policies.
  5. Uses only alleles retained in the final position profile at all three sites.

Minus-strand triplets are reverse-complemented into coding orientation. Secondary, supplementary, duplicate, QC-failed, and unmapped alignments are excluded. Overlapping mates with the same QNAME/read-group count once per codon: choose the triplet with the greater minimum quality, and discard exact-quality disagreements. Mate gaps are never filled. Reference-aligned codons after an indel are not a reconstruction of a frameshifted protein.

Codon extraction uses original SAM base qualities; it does not independently recalculate BAQ. The additional gate against the final position profile honors its BAQ/error/frequency decisions at the allele level. Consequently complete-read codon depth can be lower than marginal position depth. This stricter evidence requirement is a V2 change from the marginal-count sidecars on gene-overlap. Counts are flushed per scaffold, and the overlap cache expires as positions advance. Selection grouping is staged to Parquet and read in batches.

Codon metadata identifies the evidence policy and the exact source position profile checksum. A comparison rejects a codon table paired with a different sample profile, even when both use the same reference and gene annotation.

Selection method retained from gene-overlap

The estimator is identified as sns_snv_reference_opportunities_v2. It retains the branch's site-level SNS versus SNV split, callable-reference opportunities, and consensus/weighted integration rules. It does not introduce a corrected evolutionary-distance estimator.

For each callable, non-stop reference codon, consider its nine possible single nucleotide mutations. Each synonymous mutation contributes 1/3 synonymous opportunity. Let their sum be L_S; nonsynonymous opportunities are 3 - L_S. Sum these opportunities over callable codons for the gene. Callability requires at least 5 retained full-codon fragment observations by default; pairwise calculations use codons callable in both samples. Incomplete, ambiguous, and reference-stop codons do not contribute opportunities. Stop-producing changes are not counted as ordinary synonymous/nonsynonymous events. As on the branch, the possible stop-producing single mutations remain in the nonsynonymous opportunity complement.

Define D_N, D_S as nonsynonymous/synonymous SNS consequences and P_N, P_S as nonsynonymous/synonymous SNV consequences. Then:

dN = D_N / L_N       dS = D_S / L_S       dN_dS = dN / dS
pN = P_N / L_N       pS = P_S / L_S       pN_pS = pN / pS

There is no Jukes–Cantor or other multiple-hit correction. These rates are normalized event counts, not percentages, and are not restricted to 0–1. A zero opportunity denominator produces null. A zero dS or pS produces a null ratio, including 0/0; valid zero change rates are zero.

Classification is at each nucleotide offset, not at the whole-codon level:

Context SNS events feeding dN/dS SNV events feeding pN/pS
Sample versus reference One retained allele differs from reference More than one retained allele
Sample versus sample Each side has one retained allele and they differ Either side is polymorphic

One codon can therefore contribute fixed SNS changes at one offset and polymorphic SNV consequences at another offset.

Allele integration

For reference-relative polymorphism, differing choices are nonreference alleles. Consensus chooses the most-supported one, even if the reference allele is more abundant overall; exact top ties divide one event equally. Weighted mode uses each nonreference allele's fraction of the retained full-codon depth.

For pairwise polymorphism, differing choices are ordered unequal allele pairs. Their support is the product of the two samples' allele counts. Consensus chooses the maximum-support pair, dividing exact ties equally. Weighted mode uses the product of the two observed allele frequencies. Matching pairs contribute zero; weights are not renormalized after removing matches. Independent frequencies are used between samples, not to invent haplotypes within a read population.

For example, reference AAA and observed AAG:8, AAC:2 give a synonymous SNV event of 1 in consensus mode; weighted mode gives synonymous weight 0.8 and nonsynonymous weight 0.2. Rates then divide these by the reference opportunities.

Pairwise pN/pS is consequently a measure of polymorphic allele-pair consequences; two identical polymorphic populations can still have positive values. It is not defined as a difference between the samples' profile pN/pS values.

Correct coding context

V2 fixes the branch's known single-base-in-reference-background problem. Consequences use the full reference/observed codon pair, or the full two observed codon contexts for a sample pair. For multiple differing positions, all shortest substitution orders that avoid intermediate stops are averaged. Each offset receives its share of those path consequences. Observed contexts conditional on a selected allele choice are weighted by their support.

Thus samples GGA and GGT are synonymous even if the reference is AAA. The other two shared nonreference bases are not replaced with reference bases. This is a deliberate correction; affected multi-variant codons may differ from the old branch's results. The counting approach follows the framework of Nei and Gojobori (1986), but these raw SNS/SNV proportions are not the full corrected NG86 estimator.

Method and allele-integration settings are recorded in gene-statistics and comparison Parquet metadata. The gene-statistics table stores all six final values for filtering. Comparison tables store the four rates and drop dN_dS and pN_pS, which are costly at comparison scale and exact to derive:

from zipstrain.gene_info import with_selection_ratios

comparisons = with_selection_ratios(pl.scan_parquet("all_comparisons.parquet"))

gene_info.with_selection_ratios returns null when dS or pS is zero or null, matching the gene-statistics table. Intermediate event counts remain derivable from the codon evidence and are not additional columns in either table.

Comparison inputs and commands

zipstrain utilities compare-pair \
  --profile-1 profiles/A/A_profile.parquet \
  --profile-2 profiles/B/B_profile.parquet \
  --preprofile-dir profiles/profiling_assets \
  --calculate genome_ani+max_identical_stretch+gene_ani+gene_selection \
  --codon-counts-1 profiles/A/A_codon_counts.parquet \
  --codon-counts-2 profiles/B/B_codon_counts.parquet \
  --allele-integration weighted --output-file pair_result.parquet

Genome ANI and stretches only need the position profiles. Gene ANI additionally needs gene_info.parquet; selection calculations also need the two observed codon tables and the matching reference-codon definitions. Sample gene-statistics summaries are not inputs to pairwise calculations.

compare-pair is the only pair-level comparison command. zipstrain compare, Slurm and container runs, and Nextflow all run it per pair. It writes one Parquet table, and the selected metrics determine the key and columns for the whole table.

Selection Row key Metric columns
Genome metrics only sample_1, sample_2, genome Requested genome ANI and/or max_identical_stretch. Genome ANI includes total_positions and share_allele_pos.
Any gene metric (gene_ani or gene_selection) sample_1, sample_2, genome, gene_id Requested gene and genome metrics, plus gene_total_positions and gene_share_allele_pos.

When both levels are requested, genome metrics repeat for each qualifying gene in the genome and sample pair. To summarize a genome metric from this table, deduplicate by sample_1, sample_2, and genome first. A genome without a qualifying gene has no row in gene mode. Run genome metrics alone for complete genome coverage. Gene rows require at least --min-gene-compare-len positions callable in both samples. zipstrain_compare_kind records gene or genome in the Parquet metadata.

Row order is not guaranteed, so join or sort by these keys rather than relying on position.

--calculate takes these metrics, combined with +, on every entry point. Each metric adds its columns in this order:

Metric Adds
gene_ani gene_total_positions, gene_share_allele_pos, gene_ani
gene_selection gene_total_positions, gene_share_allele_pos, dN, dS, pN, pS (requires --collect-codons)
genome_ani total_positions, share_allele_pos, genome_ani (null without shared positions)
max_identical_stretch max_identical_stretch

all means every metric the inputs support, and zipstrain_compare_calculate records what ran. Gene metrics are skipped with a warning when no gene catalog is available, and gene_selection is skipped with a warning when no sample has a codon table. Codon tables for only some samples are an error. Naming a metric the inputs cannot support is also an error. Undefined metrics are null. V1 and V2 profiles cannot be compared with each other.

--min-gene-compare-len defaults to 1 on every entry point, so a table keeps every gene with a shared position and analyses can filter further. The plotting functions in downstream analysis apply 100. For genome-only runs it has no effect, is recorded as NA, and does not invalidate cached pairs.

Without --preprofile-dir, compare-pair calculates genome metrics only. With --pair-table it compares many pairs in one process, also for genome metrics only. --scope GENOME:GENE limits gene rows. The Nextflow workflow supports all metrics, including gene_selection: its compare jobs receive the codon tables found beside each profile.

For a collection:

zipstrain compare --profile-db profiles.csv --run-dir comparison \
  --preprofile-dir profiles/profiling_assets \
  --calculate genome_ani+max_identical_stretch+gene_ani+gene_selection

The collection writes one all_comparisons.parquet. Use --force-csv for an additional CSV copy. The V2 table method runs locally with Polars. It discovers conventional sibling codon filenames; the Python API accepts explicit per-sample paths. Each completed pair is cached with a content-addressed input/settings contract in Parquet metadata. Adding samples reuses complete matching pairs. With default validation, changed profiles, codon evidence, annotations, filters, methods, or integration settings invalidate cached pairs. Final outputs are atomically replaced. Use compare-pair inside independently managed jobs when scheduling externally.

For trusted inputs, add --skip-input-validation to zipstrain compare or zipstrain utilities compare-pair. This skips file-content hashing, the codon-to-profile SHA check, and extra scans for invalid/duplicate/out-of-range codon rows. It keeps schema, gene catalog integrity, reference/annotation metadata, profiling-filter, and required read-phased-evidence checks. Files must be valid and unchanged during a run. It does not remove the reads needed to compute comparisons or the ordering fallback for profiles without a sortedness footer.

Resuming a trusted run uses resolved path, device/inode, size, modification time and change time instead of authenticating contents. These attributes detect ordinary file changes but are not a content guarantee. Trusted and validated table caches are separate; switching modes recomputes the pairs. Matrix selection stores require a new run directory when switching modes. Matrix genome/gene ANI does not use these selection hashes. The option also reaches scheduled V2 pair jobs. In Nextflow, use --skip_input_validation true (default false); both single and batched modes forward it to each comparison. --allow-mismatch remains a separate option controlling profile-database contract checks.

The Python equivalents are validate_inputs=False on PairComparison, compare_profiles, compare_profile_collection, and matrix_workflow.run_matrix_compare.

--method table is the default. Profiling establishes coordinate order and records zipstrain_sorted_by=chrom,pos in the Parquet footer. When both inputs carry that marker, table comparison passes the declared order directly to Polars for a streaming merge join on (chrom, pos). Stretch calculations and gene interval sums reuse the result order. Polars streaming joins

Profiles without the marker use a regular coordinate join followed by a sort. If you reorder a profile outside ZipStrain, remove the marker or run zipstrain utilities sort-profile to restore the promised order.

--method matrix supports the same V2 metrics and combined gene output. Pass --stb-file and --bed-file as usual for the matrix store. With gene_selection, both methods use the sibling observed codon tables produced by --collect-codons, the same coverage threshold, and the same --allele-integration modes. The matrix method requires the default anchor kernel for gene position counts. The block kernel supports genome ANI only.

zipstrain compare --method matrix --profile-db profiles.csv --run-dir matrix_comparison \
  --stb-file reference.stb --bed-file profiles/profiling_assets/genomes_bed_file.bed \
  --preprofile-dir profiles/profiling_assets --calculate all \
  --allele-integration weighted

Matrix selection runs on the CPU in NumPy batches, regardless of the ANI backend. It stages sparse observed codon counts per sample, joins callable codons, and looks up synonymous and nonsynonymous consequences for observed codon pairs. Weighted mode multiplies their frequencies. Consensus uses the highest allele-pair support at each offset and splits ties, as in table mode. Completed selection pairs are cached separately from the matrix ANI results, so adding samples reuses old pairs. Use a fresh run directory when enabling selection on an existing matrix whose input profiles were never fingerprinted by the selection workflow.

The release benchmarks compare table and matrix selection on both genome layouts and integration modes. Benchmark charts

Known profiling-filter differences are rejected when aligning samples.

compare-pair also reads 1.x profiles: gene_ani on its own gives the legacy per-gene table. New gene-free inputs require shared annotations for gene calculations. Legacy profiles and TSV ranges remain readable by the existing legacy comparison/matrix adapters; new profiling annotations must be the authenticated Parquet catalog.

Nextflow

Use --collect_codons true (or --prepare_dnds true) and --allele_integration consensus|weighted for profiling. The workflow stages gene_info.parquet and reference_codons.parquet together. For V2 gene ANI, pass --preprofile_dir /path/to/profiling_assets. Nextflow stages the directory into single and batched comparison tasks. --mode compare is the one comparison mode: --compare_calculate selects the row level and columns described above, --compare_scope limits rows, and --allele_integration applies to gene_selection. Each sample's <sample>_codon_counts.parquet is staged when it sits beside the profile, so all includes gene_selection once every sample has one.

Scheduled runs

zipstrain compare --execution-mode slurm and container engines run V2 pairs through the same compare-pair command as Nextflow. The metrics are resolved once for all samples before any job starts, so a missing codon table fails the run up front instead of giving pairs with different columns.

identical_stretches lists where two samples are identical, not only the longest length. It is a Python function with no CLI command, and uses the table method. Its longest stretch per genome equals max_identical_stretch.

from zipstrain.compare import identical_stretches

stretches = identical_stretches("A_profile.parquet", "B_profile.parquet", min_length=1000)
stretches.collect(engine="streaming")
# sample_1, sample_2, genome, chrom, stretch_id, start, end, length,
# background_divergence, expected_runs, p_value

The last three columns say how surprising a stretch is if popANI mismatches fall at random along the genome at its genome-wide rate d = 1 - popANI. With M mismatches and S unbroken segments (one per scaffold plus one after every coordinate gap) the genome has M + S runs of matches, and a run reaches length with probability (1 - d) ** length. expected_runs is M + S times that (an E-value), and p_value is the chance that any run is at least that long. Filter on p_value instead of choosing a length by hand. A large mosaic shifts d itself; mosaic_regions refits it.

mosaic_regions finds blocks whose mismatches are much rarer or much denser than the genome's background. Recent recombination between the two lineages leaves low_divergence blocks; DNA imported from a more distant lineage leaves high_divergence blocks, which identical stretches cannot see.

from zipstrain.compare import mosaic_regions

blocks = mosaic_regions("A_profile.parquet", "B_profile.parquet")
blocks.collect(engine="streaming")
# sample_1, sample_2, genome, chrom, state, start, end, callable_positions, mismatches,
# divergence, background_divergence, log_likelihood_ratio

The model has three states with mismatch rates 1 - (1 - d) ** (1 / factor), d, and 1 - (1 - d) ** factor (factor=20 by default: twenty times fewer or more expected mutations). It runs over the runs of matches between mismatches, not over positions: a run of g matches closed by a mismatch has likelihood (1 - r) ** g * r, so a genome costs as many steps as it has mismatches. The state changes at a mismatch with probability switch_probability (default 1e-3) and restarts in the background at each scaffold. Viterbi decoding gives the blocks. The background rate starts at the genome's popANI and is refitted from background segments, so large mosaics do not set their own background. log_likelihood_ratio compares the block's state with the background; larger is stronger. A block runs from the first position after a mismatch to the mismatch that ends it, so a low_divergence block reports that closing mismatch. Lengths count shared positions: positions not covered in both samples are skipped, not counted as matches.

Read high_divergence blocks with care. Reads recruited from another species, multi-copy genes, and poorly mapped edges also concentrate mismatches, so check depth over a block before calling it an import. The model is most informative for closely related pairs (roughly popANI 99 to 99.99%). Population profiles blunt the signal, because popANI counts a mismatch only where the samples share no allele.

def range_sums(loci: pl.LazyFrame, genes: pl.DataFrame, columns, *, coordinates_sorted=False,
               chunk_size: int = 1 << 20) -> pl.LazyFrame:
    """Sum numeric position columns within every gene, including overlaps.

    Input positions must be unique within each scaffold. One streaming pass takes
    per-batch prefix sums and reads each gene's inclusive interval with a binary
    search, so no position is expanded per gene and the profile is never held in
    memory. Uncovered genes receive zero; null values count as zero.
    Set ``coordinates_sorted`` only for loci in position order within each scaffold
    run; otherwise they are sorted first. The result is lazy and computed on collect.
    """

        totals = np.zeros((len(columns), genes.height), dtype=np.float64)
        index = _index_genes(genes)
        frames = ordered.select("chrom", "pos", *[pl.col(name).cast(pl.Float64).fill_null(0) for name in columns])
        for batch in frames.collect_batches(engine="streaming", chunk_size=chunk_size):
            if batch.is_empty():
                continue
            positions = batch["pos"].to_numpy()
            values = [batch[name].to_numpy() for name in columns]
            scaffolds = batch["chrom"]
            for first, last in _scaffold_runs(scaffolds):
                entry = index.get(scaffolds[first])
                if entry is None:
                    continue
                rows, starts, ends = entry
                pos = positions[first:last]
                low = np.searchsorted(pos, starts, side="left")
                high = np.searchsorted(pos, ends, side="right")
                for k, value in enumerate(values):
                    prefix = np.r_[0.0, np.cumsum(value[first:last])]
                    totals[k, rows] += prefix[high] - prefix[low]
        return genes.select("gene_id").with_columns(
            pl.Series(name, totals[k]) for k, name in enumerate(columns))

    return pl.defer(compute, schema={"gene_id": pl.UInt64, **{name: pl.Float64 for name in columns}})

        if op in "M=X":
            if query+length > len(sequence):
                raise ValueError("CIGAR exceeds sequence length")
            for offset in range(length):
                result[reference+offset] = (sequence[query+offset].upper(), ord(qualities[query+offset])-33, query+offset)

            query += length
        elif op in "IS":
            query += length
        elif op in "DN":
            reference += length
    if query != len(sequence):
        raise ValueError("CIGAR query length does not match sequence")
    return result

def read_codon_observations(bases: dict, gene: dict, min_baseq: int = 13):
    """Yield ``(codon_index, coding_triplet, minimum_quality)`` for a read/gene.

    Require three consecutive query bases covering a complete reference codon.
    Exclude ambiguous bases, low-quality calls, insertions within a triplet,
    deletions, and skips. Minus-strand genes are reverse-complemented. Partial
    terminal codons and the explicit initial phase are excluded.
    """

        return
    origin = gene["start"]+gene["phase"] if gene["strand"] == 1 else gene["end"]-gene["phase"]
    lo, hi = min(bases), max(bases)
    for index in range(max(0, (hi-origin)//-3) if gene["strand"] == -1 else max(0, (lo-origin)//3),
                       (gene["length"]-gene["phase"])//3):

            break
        if gene["strand"] == -1 and positions[0] < lo:
            break
        if not all(p in bases for p in positions):
            continue
        calls = [bases[p] for p in positions]
        if any(b not in "ACGT" or q < min_baseq for b, q, _ in calls):
            continue
        if any(calls[i+1][2]-calls[i][2] != gene["strand"] for i in (0, 1)):
            continue
        codon = "".join(b for b, _, _ in calls)
        if gene["strand"] == -1:
            codon = codon.translate(str.maketrans("ACGT", "TGCA"))
        yield index, codon, min(q for _, q, _ in calls)

    """Two validated profiles and their shared-position join, reused by every pair analysis.

    Construction does once what each analysis needs: the profile-generation, reference and
    filter checks, optional preprofile assets, sample names and the ANI method. Every
    analysis is lazy and reads no profile rows until collected. Polars plans built on
    ``aligned`` and ``matches`` share one join and one streaming pass when collected
    together with :meth:`collect`::

        positions, blocks = pair.collect(
            pair.matches.group_by("genome").agg(pl.len()),
            pair.mosaic_regions(),
        )

    ``validate_inputs=False`` skips content hashes and codon-row validation for trusted
    inputs; schema, catalog and metadata checks remain.

    :meth:`compare` and :meth:`identical_stretches` count in NumPy batches and run their
    own pass when collected. Codon tables are only read when ``compare(calculate=...)``
    with ``gene_selection`` is collected.

    def __init__(self, profile_1, profile_2, *, preprofile_dir=None, ani_method=options.ANI_METHOD,
                 min_cov=options.COMPARE_MIN_COV, sample_1=None, sample_2=None,
                 codon_counts_1=None, codon_counts_2=None, allele_integration=options.ALLELE_INTEGRATION,
                 validate_inputs: bool = True):
        from zipstrain import gene_info as gi, matrix_pairs as mp
        if min_cov < 1:
            raise ValueError("min_cov must be positive")
        self.profiles = (profile_1, profile_2)
        self.preprofile_dir = None if preprofile_dir is None else Path(preprofile_dir)
        self.gene_file, self.genes = None, None
        if self.preprofile_dir is not None:
            self.gene_file = self.preprofile_dir/"gene_info.parquet"
            gi.validate_profile_assets(list(self.profiles), self.gene_file)
            self.genes = gi.read_gene_info(self.gene_file)
        self.names = _pair_names(profile_1, profile_2, sample_1, sample_2)
        self.codon_counts = (codon_counts_1, codon_counts_2)
        self.allele_integration = allele_integration
        self.validate_inputs = validate_inputs
        self.min_cov = min_cov
        self.ani_method, _threshold = mp.parse_matrix_ani_method(ani_method)
        require_same_profile_generation(self.profiles)
        # Reject incompatible samples before any analysis spends time on them.
        self.aligned: pl.LazyFrame = _align_inputs(
            _alignment_input(profile_1), _alignment_input(profile_2), min_cov)

    @property
    def matches(self) -> pl.LazyFrame:
        """Shared positions as ``chrom``, ``genome``, ``pos`` and whether they match under ``ani_method``."""
        match = getattr(PolarsANIExpressions(), self.ani_method)() > 0
        return self.aligned.select("chrom", "genome", "pos", match.alias("match"))

    @staticmethod
    def collect(*frames: pl.LazyFrame, engine: str = "streaming") -> list[pl.DataFrame]:
        """Collect several analyses together, so Polars runs their shared join once."""
        return pl.collect_all(list(frames), engine=engine)

    def compare(self, calculate=options.CALCULATE, *,
                min_gene_compare_len=options.MIN_GENE_COMPARE_LEN) -> pl.LazyFrame:
        """Return genome or gene comparison rows, as described in :func:`compare_profiles`."""
        from zipstrain import codons
        if min_gene_compare_len < 1:
            raise ValueError("min_gene_compare_len must be positive")
        codon_tables = dict(zip(self.names, self.codon_counts, strict=True))
        calculations = options.resolve_metrics(
            calculate, genes_available=self.genes is not None and self.genes.height > 0,
            codon_tables_present=[name for name, counts in codon_tables.items() if counts is not None],
            codon_tables_missing=[name for name, counts in codon_tables.items() if counts is None],
        )
        rates = None
        if "gene_selection" in calculations:
            def rates():
                # At collect time, so building the plan reads no codons and hashes no profile.
                for counts, positions in zip(self.codon_counts, self.profiles, strict=True):
                    if self.validate_inputs and pl.read_parquet_metadata(counts).get("zipstrain_source_profile_sha256") != _file_digest(positions):
                        raise ValueError("Codon evidence does not match its sample position profile")
                return codons.pairwise_selection(*self.codon_counts, self.gene_file, min_cov=self.min_cov,
                                                 allele_integration=self.allele_integration,
                                                 validate_inputs=self.validate_inputs)
        universe = [_as_lazy_profile(source).select(pl.col("genome").cast(pl.String)).unique()
                    for source in self.profiles]
        return _compare_aligned(
            self.aligned, self.names, calculations=calculations, ani_method=self.ani_method,
            min_gene_compare_len=min_gene_compare_len, genes=self.genes, rates=rates,
            genome_universe=[*universe, *_catalog_genomes(self.preprofile_dir, self.genes)],

        positions at one rate. A three-state hidden Markov model over the runs of matches between
        mismatches finds blocks that fit ``factor`` times fewer (``low_divergence``, such as recent
        recombination) or ``factor`` times more (``high_divergence``, such as DNA imported from a
        more distant lineage) expected mutations better than the background. The background
        rate starts at the genome's popANI and is refitted without the blocks.
        ``switch_probability`` is the prior chance that the state changes at a mismatch.

        Return one row per block: ``sample_1``, ``sample_2``, ``genome``, ``chrom``, ``state``,
        ``start``, ``end``, ``callable_positions``, ``mismatches``, ``divergence``,
        ``background_divergence`` and ``log_likelihood_ratio`` (the block's log-likelihood in its
        state minus in the background state; larger is stronger). A block runs from the first
        position after a mismatch, or the scaffold's first shared position, to the mismatch that
        ends it, or the scaffold's last shared position. Lengths count shared positions, so
        positions not covered in both samples are skipped rather than counted as matches.

        also look like ``high_divergence`` blocks, so check depth before reading them as imports.

        return (
            _mosaic_events(self.matches)
            .group_by("genome").map_groups(decode, schema=_MOSAIC_SCHEMA)
            .sort("genome", "chrom", "start")
            .select(pl.lit(self.names[0]).alias("sample_1"), pl.lit(self.names[1]).alias("sample_2"),
                    *_MOSAIC_SCHEMA)
        )

def compare_profile_collection(profiles, run_dir, *, preprofile_dir=None,
                               calculate=options.CALCULATE, ani_method=options.ANI_METHOD,
                               min_cov=options.COMPARE_MIN_COV,
                               min_gene_compare_len=options.MIN_GENE_COMPARE_LEN,
                               codon_counts=None, allele_integration=options.ALLELE_INTEGRATION,
                               memory_limit_gb=16.0, workers=1, validate_inputs: bool = True):
    """Run/resume V2 Polars comparisons for named profile paths and export Parquet.

    ``profiles`` is an iterable of ``(sample_name, profile_path)``. Codon files
    may be supplied by sample name in ``codon_counts``; otherwise use sibling
    ``<sample>_codon_counts.parquet`` files. Cache each pair under
    ``intermediate_files/v2_pairs`` with a content-addressed input/settings
    contract in Parquet metadata. Only complete, authenticated pair outputs are
    reused by default. Added samples compute only new pairs; changed content/settings
    invalidate validated results. Final exports are atomically replaced and contain only
    the requested collection's pairs. Selection metrics use the explicitly documented gene-overlap SNS/SNV definitions.

    Inputs are validated and each sample's codons packed once, however many pairs it joins.
    ``validate_inputs=False`` skips content hashes and codon-row validation, using file
    attributes for cache identity. It trusts contents; schema and metadata checks remain.
    Trusted cache entries cannot be reused by a validated run.
    ``workers`` runs that many pairs in separate processes, within the CPU allocation and
    ``memory_limit_gb``; ``"auto"`` chooses the count. Results do not depend on it. More than
    one worker re-imports the calling script, so a script needs ``if __name__ == "__main__"``.
    """
    from zipstrain import codons, gene_info as gi, matrix_pairs as mp, pair_selection, utils
    from zipstrain.resource_limits import job_pool, map_jobs
    if min_cov < 1:
        raise ValueError("min_cov must be positive")
    if min_gene_compare_len < 1:
        raise ValueError("min_gene_compare_len must be positive")
    profiles = sorted((str(name), Path(path)) for name, path in profiles)
    if len(profiles) < 2 or len({name for name, _ in profiles}) != len(profiles):
        raise ValueError("At least two uniquely named samples are required")
    require_same_profile_generation([path for _, path in profiles])
    genes, calculations, codon_paths = resolve_collection_metrics(profiles, preprofile_dir, calculate, codon_counts)
    selection = "gene_selection" in calculations
    gene_rows = any(metric in options.GENE_METRICS for metric in calculations)
    # Genome rows do not depend on the threshold, so it must not invalidate their cache.
    gene_threshold = min_gene_compare_len if gene_rows else None
    if preprofile_dir is not None:
        metadata = gi.validate_profile_assets([p for _, p in profiles], Path(preprofile_dir)/"gene_info.parquet")
    else:
        metadata = {gi.SCHEMA_KEY: "2"}
    metadata.update({"zipstrain_compare_reference_id": metadata.get(gi.REFERENCE_ID, "NA"),
                     "zipstrain_compare_annotation_id": metadata.get(gi.ANNOTATION_ID, "NA"),
                     "zipstrain_compare_min_cov": str(min_cov),
                     "zipstrain_compare_min_gene_compare_len": "NA" if gene_threshold is None else str(gene_threshold),
                     "zipstrain_compare_allele_integration": allele_integration,
                     "zipstrain_compare_selection_method": codons.METHOD if selection else "not_calculated",
                     "zipstrain_compare_kind": "gene" if gene_rows else "genome",
                     utils.COMPARE_ENGINE_METADATA_KEY: "table",
                     "zipstrain_compare_ani_method": ani_method,
                     "zipstrain_compare_calculate": "+".join(calculations),
                     "zipstrain_allele_integration": allele_integration,
                     "zipstrain_selection_method": codons.METHOD if selection else "not_calculated"})
    run_dir = Path(run_dir)
    cache = run_dir/"intermediate_files"/"v2_pairs"
    cache.mkdir(parents=True, exist_ok=True)
    hashes = {name: utils.input_fingerprint(path, validate_inputs=validate_inputs) for name, path in profiles}
    codon_hashes = {name: utils.input_fingerprint(path, validate_inputs=validate_inputs)
                    for name, path in codon_paths.items()} if selection else {}
    pairs = {}
    for i, (name_1, _) in enumerate(profiles):
        for name_2, _ in profiles[i+1:]:
            contract = {"version": "v2-pair-5", "names": [name_1, name_2],
                "profiles": [hashes[name_1], hashes[name_2]], "calculate": calculations,
                "ani_method": ani_method, "min_cov": min_cov,
                "min_gene_compare_len": gene_threshold, "allele_integration": allele_integration,
                "codons": [codon_hashes.get(name_1), codon_hashes.get(name_2)], **metadata}
            identity = gi.content_digest(contract)
            pairs[name_1, name_2] = identity, cache / f"{identity}.parquet"
    missing = {pair: value for pair, value in pairs.items()
               if utils._read_custom_parquet_metadata(value[1]).get("zipstrain_comparison_id") != value[0]}
    if missing:
        method, _threshold = mp.parse_matrix_ani_method(ani_method)
        directory = Path(preprofile_dir) if preprofile_dir is not None else None
        paths = dict(profiles)
        _clear_shared_inputs()
        # Fail on any unusable profile before starting worker processes.
        for path in paths.values():
            _shared_input(path)
        rows = max(pl.scan_parquet(path).select(pl.len()).collect().item() for path in paths.values())
        worker_count, threads = _pair_workers(workers, len(missing), memory_limit_gb, rows)
        with job_pool(worker_count, threads) as pool:
            rates = {}
            if selection:
                rates = dict(zip(pairs, pair_selection.stage_selection_pairs(
                    profiles, hashes, directory/"gene_info.parquet", cache.parent/"pair_selection",
                    min_cov=min_cov, genome="all", allele_integration=allele_integration,
                    memory_limit_gb=memory_limit_gb, codon_tables=codon_paths, codon_digests=codon_hashes,
                    pool=pool, workers=worker_count, validate_inputs=validate_inputs,
                ), strict=True))
            map_jobs(pool, _compare_pair_job, [
                _PairJob(pair, (paths[pair[0]], paths[pair[1]]), target, identity, metadata, calculations,
                         method, min_cov, min_gene_compare_len, directory, rates.get(pair))
                for pair, (identity, target) in missing.items()
            ])
        _clear_shared_inputs()
    files = [target for _, target in pairs.values()]
    output = run_dir / "all_comparisons.parquet"
    with TemporaryDirectory(dir=run_dir) as staging:
        temporary = Path(staging) / output.name
        pl.scan_parquet(files).sink_parquet(temporary, engine="streaming", compression="zstd", metadata=metadata)
        utils.replace_file(temporary, output)
    return output

def finish_profile_outputs(profile_file, gene_info_file=None, *, bam_file=None,
                           collect_codons=False, min_mapq=0, min_baseq=13,
                           min_read_ani=PROFILE_MIN_READ_ANI_DEFAULT, read_inclusion=PROFILE_READ_INCLUSION_DEFAULT, min_freq=0.01,
                           allele_integration="consensus", reference_id=None, codon_extractor=None):
    """Finalize V2 profile identity, gene statistics, and optional codon evidence.

    Strip legacy gene labels, preserve existing Parquet metadata, and attach the
    authenticated preprofile identities. Write the agreed 15-column gene table.
    With ``collect_codons``, require a BAM and catalog, write observed triplets,
    and calculate the gene-overlap SNS/SNV reference selection
    metrics. Shared by Python profiling and the optional backend adapter.
    """
    from zipstrain import codons, gene_info as gi

    profile_file = pathlib.Path(profile_file)
    existing = utils._read_custom_parquet_metadata(profile_file)
    metadata = profile_output_metadata(existing, gene_info_file, min_mapq=min_mapq,
        min_baseq=min_baseq, min_read_ani=min_read_ani, read_inclusion=read_inclusion,
        min_freq=min_freq, reference_id=reference_id)
    if collect_codons and (bam_file is None or gene_info_file is None):
        raise ValueError("Observed codons require a BAM and preprofile gene_info.parquet")
    source = pl.scan_parquet(profile_file)
    names = source.collect_schema().names()
    columns = [name for name in names if name not in ("gene", "gene_id")]
    # Python profiling writes the final metadata and no gene labels up front, so the
    # profile is rewritten only for native backends and legacy files.
    if columns != names or existing != metadata:
        rewritten = profile_file.with_suffix(".v2.parquet")
        source.select(columns).sink_parquet(rewritten, compression="zstd", metadata=metadata)
        utils.replace_file(rewritten, profile_file)
    selection = None
    if collect_codons:
        codon_file = profile_file.with_name(profile_file.name.replace("_profile.parquet", "_codon_counts.parquet"))
        if codon_file == profile_file:
            codon_file = profile_file.with_name(profile_file.stem+"_codon_counts.parquet")
        codons.write_codon_counts(bam_file, profile_file, gene_info_file, codon_file,
            min_baseq=min_baseq, min_mapq=min_mapq, min_read_ani=min_read_ani,
            read_inclusion=read_inclusion, extractor=codon_extractor)
        selection = codons.reference_selection(codon_file, gene_info_file, allele_integration=allele_integration)
        metadata["zipstrain_selection_method"] = codons.METHOD
        metadata["zipstrain_allele_integration"] = allele_integration
    stats = (gi.gene_statistics(pl.scan_parquet(profile_file), gene_info_file, selection=selection,
                                coordinates_sorted=metadata.get(PROFILE_SORTED_METADATA_KEY) == PROFILE_SORTED_METADATA_VALUE)
             if gene_info_file is not None else empty_gene_stats_table())
    stats_file = profile_file.with_name(profile_file.name.replace("_profile.parquet", "_gene_stats.parquet"))
    if stats_file == profile_file:
        stats_file = profile_file.with_name(profile_file.stem+"_gene_stats.parquet")
    table_metadata = {key: value for key, value in metadata.items() if key != PROFILE_SORTED_METADATA_KEY}
    stats.sink_parquet(stats_file, compression="zstd", metadata=table_metadata)
